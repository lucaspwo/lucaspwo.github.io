## Conventions & constraints

- Do: mirror every EN page you add/edit under `br/` with the same filename.
- Do: keep the nav block edits in sync across every `.html` file (no shared partial exists).
- Do: put post images under `projetos/<slug>/`, not `img/` (the latter is legacy theme demo content, still referenced by `about.html` — don't delete).
- Don't: assume Jekyll/Hugo processing — there is none on this branch (no `_config.yml`), but Pages `build_type` is `"legacy"` (Jekyll-based); avoid introducing `_`-prefixed dirs on this branch without also adding `.nojekyll`, or they'll be silently dropped from the deploy.
- Don't: touch `builder/` on this branch — it's an untracked leftover, not part of this branch's git history.
- Don't: confuse this branch's architecture with `master`'s (Nunjucks/Markdown pipeline) when reading code — check `git branch`/`git status` output before editing.

## Common change recipes

1. **Add a new post/project:**
   1. Copy `proj_template.html` to `<slug>.html` (EN) and `br/<slug>.html` (PT).
   2. Create `projetos/<slug>/` with the post's images.
   3. Edit content by hand (no templating).
   4. Add a card to `index.html` and `br/index.html` home listings.
   5. If it should appear in the main menu, add `<li><a href="slug.html">Name</a></li>` to the nav block in every page that should show it (`index.html:50-54` pattern, repeated per file).

2. **Change global styles:** edit `scss/style.scss` or `scss/_custom-settings.scss`, then `npx gulp sass`. For one-off tweaks that shouldn't live in the theme's Sass, edit `css/custom.css` directly (hand-maintained, not generated).

3. **Add a third-party script:** drop it in `js/vendor/`, add its path to `gulpfile.js:24-34`, run `npx gulp scripts`.
